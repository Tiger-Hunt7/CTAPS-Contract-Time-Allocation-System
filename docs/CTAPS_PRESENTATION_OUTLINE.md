# CTAPS Presentation — Portfolio Outline

## Contract Time Allocation and Priority System

### Core message

**The point is not to automate judgment. The point is to focus judgment where it matters most.**

CTAPS was presented as a structured way to direct limited contract-monitoring time toward the contracts where oversight could matter most.

## Workflow presented

```text
Lite
  ↓
Assess
  ↓
Final
  ↓
Allocate
```

### 1. Lite

Use existing contract information for fast preliminary triage.

### 2. Assess

Collect structured employee judgment for operational factors that cannot be determined reliably from database fields alone.

### 3. Final

Combine objective and assessment information into an explainable final CTAPS ranking, with management review retained as a control.

### 4. Allocate

Translate the ranking into monitoring levels and review cadence so that staff time is distributed according to relative contract priority.

## Intended governance

The presentation emphasized that CTAPS was not intended to make autonomous contract-management decisions. Scores were intended to organize attention, surface uncertainty, and create a common framework for management review.

## Portfolio significance

The presentation captures the strongest version of the original CTAPS concept. The subsequent stakeholder response is equally important: the architecture solved a broader problem than management was asking the team to solve at that time.

That mismatch is discussed in [Project Retrospective](PROJECT_RETROSPECTIVE.md), particularly the section on **concept continuation in vibe coding**.
